# 首版开发与验收计划

状态：内容/格式编辑、页面/元素操作和撤销工具已实现，尚未发布。当前证据：

- 真实 DSH 已加载面板，并通过所选模型完成读取、直接修改（无确认）、一次撤销和重做。
- `pnpm test:browser`
  使用真实 React 编辑器，验证直接修改、过期请求拒绝、撤销重做、保存重开及标签切换后的状态保留。
- 合成文稿验证图片、表格、备注、图表及内嵌工作簿内容；另有用户授权的本地文稿往返测试，不将正文加入仓库。
- `pnpm check`
  覆盖宿主授权、会话隔离、界面边界、保存冲突与失败。重新构建后应重新启动 DSH 加载代码。
- 未完成：发布包的独立安装验收、自动覆盖保存、跨页原子修改、完整变更通知、所有 PPTX 特性的保真验证。

## 新增幻灯片切片

`add_pptx_slide` 在末尾或指定页后新增空白页；`add_pptx_text`
在当前页新增文本框，分别保留撤销步骤和现有版本、保存保护。
`tests/e2e/add-slides.spec.mjs`
使用真实编辑器验证新增页、标题、正文、撤销/重做、重复请求拒绝、插入中间页、保存的 OOXML 页序和重新打开。该浏览器测试替代了宿主注册和文件选择边界，不能作为真实模型对话证据。

## 格式与页面、元素操作

`edit_pptx` 接入字体、段落/垂直对齐、间距、列表、填充和描边； `operate_pptx`
接入页面导航/复制/删除/排序/隐藏、形状插入、元素复制/删除/选区对齐/等间距分布及撤销/重做。
`read_pptx`
提供选区、格式和能力列表，避免 Agent 通过源码猜测能力。真实 Chrome 用例验证段落居中不移动文本框、撤销/重做、保存重开，以及指定元素删除和页面复制保存。多元素排列逐项占用撤销历史，没有跨元素原子事务；表格/图表数据、导入图片、母版、动画、组合及图层顺序尚未接入。这些用例使用替代的宿主注册和文件选择边界。另以新发送的合成附件完成真实 DSH 模型验证：段落居中、颜色、斜体、32 磅字号、复制/移动页面及撤销/重做；通过画布计算样式确认格式实际生效，未写入磁盘。联调发现并修复了模型工具顶层参数必须为对象的限制。

## 已确定的需求

- 在聊天旁的面板中打开已有 PPTX，保留组件的完整编辑器。
- Agent 读取当前编辑状态后直接修改，无需额外确认，随后支持撤销。
- 应用后立即更新页面；磁盘保存是另一项操作，覆盖用户打开的原文件。
- 可靠变更通知和保存失败处理就绪后再开启自动保存。
- 选中元素后“改这里”留到下一期。

无需重新设计组件工具栏或另写一份完整 PRD。先完成下面的开发切片。

## 模块职责

下面是实现职责划分，具体目录和接口在第 0 步确认后落地。

| 模块       | 职责                                                       |
| ---------- | ---------------------------------------------------------- |
| 宿主接入   | 注册插件、编辑面板和 Agent 工具，处理通信与资源释放        |
| 文档会话   | 关联打开的文件与编辑器，协调当前版本、修改回执和保存状态   |
| 编辑器适配 | 通过公开 API 读取当前内容、应用修改、撤销、重做和序列化    |
| 直接修改   | 校验操作与目标，直接应用有效请求，拒绝过期或重复执行的请求 |
| 文件保存   | 只写用户打开的文件，处理外部变更、写入失败、顺序和成功回执 |

编辑器持有当前可编辑内容。服务端可保留文件标识和保存版本信息，但不维护一份独立编辑副本来覆盖编辑器。是否发生修改、是否已进入撤销历史、是否已保存到磁盘分别记录。

## 开发顺序

### 0. 固定接口与最小运行方式

- 验证发布版 DSH 的接入点及组件完整编辑器的加载方式，确认所选 UI 绑定。
- 核验读取内容前如何提交正在输入的文字，以及修改、撤销、序列化的实际语义。
- 定义文档标识、版本、修改回执标识、操作列表与错误结果，绑定到当前文档会话。
- 将必要验证整理成可重复运行的测试或示例，输出实际版本、能力和限制。

完成条件：插件能在真实 DSH 中加载并卸载；接入点和状态读取方式有可复现证据。这一阶段不启用模型修改或自动覆盖文件。

### 1. 打通打开、手动编辑与保存

- 从用户明确打开的文件创建会话，在聊天旁显示完整编辑器。
- 保持组件主题、工具栏、缩略图和属性面板正常，限制宿主 CSS 对组件的影响。
- 将手动保存接到当前会话的序列化结果，再覆盖原文件。
- 明确显示加载、未保存、保存中、已保存和失败状态；处理切换文件及关闭面板。

完成条件：在真实 DSH 中打开测试 PPTX，手动修改并保存，再打开同一文件可看到改动；保存失败时保留编辑内容且不显示“已保存”。

### 2. 打通 Agent 直接修改与撤销

- 接入 DSH 已配置的模型，通过工具读取当前文档并生成结构化修改请求。
- 第一组操作围绕可验证的文本、样式和位置修改，逐项声明支持范围。
- 收到请求后直接应用，无需展示确认卡片；返回真实应用结果与更新后的版本，不自动写磁盘。
- 应用前校验文档版本和目标。读取后的手动修改、撤销或文档切换使旧请求失效。
- 应用成功后更新页面，支持撤销和重做；失败不报告成功，重复请求不重复应用。

完成条件：用户在真实对话中要求修改，页面直接更新且不要求确认，撤销可恢复。至少验证一次“读取后手动编辑，再发送旧版本修改”的拒绝路径。

先交付单页可运行切片。跨页一次撤销需通过公开接口的事务和失败测试后再开放；不把逐页执行、只撤销最后一页标记为跨页撤销支持。此项不阻塞前两步开发。

### 3. 扩展批量操作与可靠自动保存

- 跟踪上游批量事务和编辑变更事件的发布，在实际包中验证后接入。
- 跨页应用、撤销和重做必须覆盖所有目标页；中途失败不能留下部分修改。
- 变更通知需覆盖连续编辑、手动编辑、Agent 应用、撤销和重做。
- 自动保存合并短时间的多次修改，串行写入，区分正在保存的版本和最新编辑版本。
- 检测原文件的外部变更；出现冲突或写入失败时提示并保留内存内容，避免静默覆盖。

完成条件：连续编辑、应用后撤销、保存过程中继续编辑及保存失败恢复均符合预期。能力未验证时保持显式保存，不用一次性的 dirty 标志冒充完整变更通知。

### 4. 完成首版交付验证

- 从构建产物安装到干净的本地 DSH 配置，验证实际运行依赖、静态资源和卸载。
- 使用合成的多页 PPTX，覆盖文字、形状、图片、表格与图表的保留和保存重开。
- 实测对话、直接修改、重复请求、过期请求、撤销、保存、重开及多个会话之间的隔离。
- 验证模型失败、文件失效、连接中断、面板关闭和插件卸载后的处理。
- 同步更新中英双语的安装与使用说明，列出受支持操作和已验证文件类型、特性及限制。

完成条件：本地检查、真实浏览器、真实 DSH 对话和文件重开都有证据。组件测试或 CI 通过不能单独证明整套插件可用；npm 发布仍需另行授权。

## 关键验收场景

| 场景                          | 必须观察到的结果                                 |
| ----------------------------- | ------------------------------------------------ |
| 输入文字后立即发起 Agent 操作 | 读取已提交的最新内容，或明确等待输入完成         |
| 读取后继续手动编辑            | 旧请求被拒绝，不覆盖新编辑                       |
| 有效请求或重复请求            | 有效请求立即生效，重复请求不能再次修改           |
| Agent 应用后撤销、重做        | 修改范围内的内容一致恢复，不丢失之前的手动编辑   |
| 多页操作中途失败              | 整批没有生效，或恢复到整批之前的状态             |
| 保存中产生新编辑              | 旧保存回执不把新编辑标记为已保存                 |
| 写入失败或磁盘文件被外部修改  | 原因可见，内存编辑保留，不报告保存成功           |
| 切换文件、关闭面板或卸载      | 旧响应不能修改新文档，监听器与待执行操作正确释放 |
| 宿主与完整编辑器共同显示      | 工具栏、颜色和画布尺寸正确，无全局样式污染       |

测试数据使用可重复生成的合成文件，不把用户 PPTX、对话或凭据加入仓库。真实模型联调沿用用户的本地 DSH 配置；缺少配置时明确标记联调未完成。
