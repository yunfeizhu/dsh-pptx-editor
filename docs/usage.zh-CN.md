# 使用 dsh-pptx-editor

[English](usage.md) · [简体中文](usage.zh-CN.md)

## 安装 1.0.0

先安装 Node 24 并配置 DeepSeek Harness，再安装预构建的 npm 包：

```sh
dsh plugin --profile web add dsh-pptx-editor@1.0.0
dsh web
```

安装包包含宿主插件、浏览器客户端和编辑器资源。安装后不要再加载源码的
`dsh.patch.yml`，否则会重复注册插件。npm 安装无需本地构建。如需自行构建安装包，克隆仓库后依次运行
`pnpm install --frozen-lockfile`、`pnpm build` 和 `pnpm check:package`，再用同一
`dsh plugin` 命令安装生成的 `.cache/packages/dsh-pptx-editor-1.0.0.tgz`。

### 从旧名称迁移

先保存打开的文稿并停止 DSH Web。如果之前安装了旧包，运行
`dsh plugin --profile web remove dsh-pptx-viewer`，再安装新包并重启 DSH
Web。新名称对应独立的 npm 包，更新旧包不会自动切换已有安装。浏览器自动保存的恢复标识保持不变。

卸载新包时运行 `dsh plugin --profile web remove dsh-pptx-editor`，再重启 DSH
Web。卸载不会删除浏览器恢复数据。

## 从源码启动

开发时需要 Node 24、`package.json` 中指定版本的 pnpm，以及配置好的本机 DeepSeek
Harness。

```sh
git clone https://github.com/yunfeizhu/dsh-pptx-editor.git
cd dsh-pptx-editor
corepack enable
pnpm install --frozen-lockfile
pnpm dev
```

宿主兼容基线为 DSH CLI `0.1.5-rc.1` 及公开插件包 `0.1.5-rc.2`。插件 `1.0.0`
打包了 `pptx-react-viewer`
`3.19.2`。启动补丁注册本地构建产物；启动时不使用该补丁即可停用该构建。

如需让开发环境与平时的 DSH 配置分开：

```sh
pnpm build
DSH_HOME="$PWD/.dsh-dev" dsh web --patch ./dsh.patch.yml --port 3082 --no-open
```

打开 DSH 输出的登录链接。新配置目录需要先在 DSH 设置中配置模型。插件使用当前对话选择的模型，无需另配服务商密钥。

请使用最新版 Chrome 或 Edge，浏览器需支持原生文件选择器和保留状态的 iframe 移动。服务必须监听
`127.0.0.1`；此版本不支持编辑远程服务器文件。

## 打开与编辑

### 从聊天附件打开

在新对话或已有对话中点击 **添加附件**，选择一个不超过 50 MiB 的 `.pptx`
文件，连同需求一起发送。插件会在右侧打开刚发送的附件。预览时可以说“预览一下这个幻灯片”；加载后，可继续在同一对话中直接修改。

侧栏“开始”页不再提供独立的 PPTX 入口。发送附件即可开始，之后可通过对话重新打开编辑器。

仅选择附件、尚未发送消息时不会打开。此版本使用 DSH 的公开消息接收事件，当前没有草稿附件上传完成通知。刷新页面或首次打开旧对话时，会从已加载的历史消息中恢复最近的 PPTX 附件；如果你主动关闭了 PPTX 标签，刷新后会保持关闭。关闭状态按对话保存在当前浏览器页签中。通过对话要求重新打开，或发送新的 PPTX 附件，都可以再次打开。如果浏览器存储不可用，会跳过历史附件的自动打开，通过对话打开仍可使用。这里只记录关闭状态，不存储文稿。向上翻阅旧消息不会替换当前文稿。每条消息只发送一个 PPTX，以明确选择要编辑的文稿。加载替换附件时会暂时锁定旧编辑器；未保存的修改需由用户决定是否丢弃，下载失败会保留旧文稿。

使用组件的**保存**按钮下载编辑后的 PPTX，保存位置由浏览器的下载设置决定。本机原文件和聊天附件保持不变，插件不会覆盖它们。

### 编辑已打开的文稿

1. 使用组件完整的工具栏、缩略图和属性面板编辑；需要更多空间时展开 DSH 面板至全屏。
2. 在对话中提出针对指定页的修改，例如：“用 PPTX 工具把封面标题改成 Project
   Nova。”
3. Agent 直接更新画布，无需额外确认。之后可用编辑器的 **Undo** 和 **Redo**
   撤销、重做。
4. 点击组件的**保存**按钮（软盘图标）下载编辑后的 PPTX。需要打开其他文件时，使用**文件 → 打开 → 浏览此设备**，插件不再提供额外的文件操作栏。

面板误关或隐藏后，可以在对话中说“重新打开右侧的 PPTX”。`open_pptx`
工具会恢复保留的编辑器，等到面板可见且文稿就绪后才返回成功。同一浏览器页面内会保留未保存修改和撤销历史；刷新页面后重新打开原附件，组件可以提示是否恢复匹配的自动保存副本。本机选择的文件需要重新选择，恢复副本不包含撤销历史。当前插件 API 不支持直接点击原生附件卡片打开。

`read_pptx`
返回实时文档、当前选中的元素 ID、可用撤销历史、支持的操作、文字片段、格式和几何信息。`edit_pptx`
修改指定页的一个顶层元素。位置、尺寸和字号单位为 CSS 像素，旋转单位为度（PowerPoint 中的 32 磅约为 42.67 像素）。替换文字会沿用第一个片段的格式并替换富文本片段；只改格式会保留片段边界及未修改的样式。成功返回
`status: applied` 和新版本，工具不会写入磁盘。

元素级格式摘要描述第一个段落；逐片段格式会包含实际设置的段落属性，因此保存重开后，导入的缩进值优先于继承的默认值。

#### 跨页批量修改元素（0.2.0）

例如：“把第一页和第二页的标题都居中。”Agent 先读取两个目标，然后调用
`edit_pptx_batch`，根参数为
`{documentId, version, summary, edits: [{slideIndex, elementId, patch}, ...]}`。一次接受 1–100 个不重复的顶层元素，支持与
`edit_pptx` 相同的修改字段。全部目标校验通过后，再通过公开的 `updateElements`
一起应用，整批只占一个独立撤销步骤，不切换当前页或选中元素。目标无效或版本过期时整批拒绝；结果不确定时仍需重读后再决定是否重试。没有实际变化时返回
`unchanged`，撤销步骤为零。

批量操作不包括增删页面／元素、表格／图表数据修改，也不写入磁盘。不同工具调用仍各自保留历史步骤。

## 文字格式与段落对齐

例如：“把这个标题居中、加粗、改成蓝色，行距设为 1.5 倍。”Agent 读取当前选区和文档后修改；目标不明确时，应先确认需要修改哪个元素。

| 字段               | 支持的修改                                                         |
| ------------------ | ------------------------------------------------------------------ |
| `patch.textStyle`  | 字体、字号、RGB 颜色、粗体、斜体、下划线、删除线                   |
| 段落               | `align`：左对齐/居中/右对齐/两端对齐；`vAlign`：顶部/垂直居中/底部 |
| 间距               | 倍数行距、段前/段后间距、段落左右边距、首行缩进、文本框四边内边距  |
| 列表               | `listType`：项目符号/编号/无列表，作用于框内所有段落               |
| `patch.shapeStyle` | 文本框和形状的纯色/无填充、填充色、描边色及宽度                    |
| 几何               | x/y/宽/高、旋转、水平/垂直翻转                                     |

段落对齐修改的是**现有文本框内的文字**，不会缩窄或移动文本框。格式目前作用于整个元素，不支持只改选中的部分字符。新增文本也支持同样的
`textStyle` 字段，并优先于原有的 `fontSize`、`color`、`bold` 字段。

导入文稿中的自定义编号（如字母、罗马数字）请在编辑器界面转换；对话列表使用带点的十进制数字编号。

### 页面、形状、元素与撤销

`operate_pptx` 的 `action` 对象同样要求最新文档 ID 和版本：

- `navigate`：切换预览页面。编辑操作会先校验文档版本及目标，再自动切换到指定页。
- `duplicate-slide`、`delete-slide`、`move-slide`、`set-slide-hidden`：复制、删除、移动和隐藏页面。索引从 0 开始，移动目标是最终位置。复制后选中新页，不能删除最后一页。
- `add-shape`：新增矩形、圆角矩形、椭圆、三角形、菱形、六边形、V 形箭头或右箭头，可附带有格式的文字。
- `duplicate-element`、`delete-elements`：复制或删除指定页的顶层元素。副本使用新 ID，默认向右、向下各偏移 16 像素。
- `arrange-elements`：两个以上未旋转元素，在选区整体范围内左/中/右、上/中/下对齐；三个以上元素可水平或垂直等间距分布。它对齐的是选区内的元素框，不是段落，也不是按整页对齐。空间不足以形成无重叠间距时会拒绝分布操作。
- `undo`、`redo`：撤销/重做编辑器共享历史中的一步，包含手动编辑，不仅限于 Agent 操作。

例如：“复制第 2 页，把副本移到最前面”“删除这个形状”“把这三个框顶部对齐”“撤销上一步”。多元素排列逐个调用公开更新接口，每个实际变化的元素占一步撤销。操作失败时可能保留部分修改，应先读取实际状态再决定是否重试，不会自动回滚整串操作。

`read_pptx` 成功后会返回 `preview.status: ready` 和页数。`readProjection`
说明返回给 Agent 的文字、格式与几何信息范围；包含表格单元格及样式（最多 100 行、30 列，超出时标记截断），也包含图表分类、数据系列和样式（最多 20 个系列、1000 个数据点）。备注和图片内文字不包含在该工具结果中。这不代表右侧视觉预览缺少这些对象。简单预览无需额外运行 Shell 脚本或转换文件。

发起 Agent 操作或下载文件前，请先完成正在输入的文字。手动交互、翻页、撤销或切换文稿都会使此前读取的版本过期，Agent 需要重新读取后再修改。每次打开文件都会生成独立的文档标识，即使文件名和大小相同。

每轮新的修改都需要先调用
`read_pptx`，回答澄清问题或刷新页面后也需要重新读取。`Stale edit`
会在产生修改之前拒绝这次请求，Agent 应重读实际状态、重新判断后再重试。这类拒绝会返回给对话工具，不再在编辑区重复弹错，也不表示自动保存失败。实际编辑失败仍会在编辑区显示。

自动保存更新内部存档 ID、页码及表格默认锁定属性不会推进编辑版本；文稿内容、元素标识和页面结构仍会被校验。

### 通过对话新增幻灯片和文本

例如：“在末尾新增第三页，标题写‘下一步计划’，正文文本框写‘明确目标、开发、验证’。”也可以说：“在第 1 页后插入一张空白幻灯片。”Agent 会先读取文稿，再新增页面，并在新的当前页添加文字。修改直接显示，无需额外确认。

- `add_pptx_slide`
  每次新增一页空白幻灯片并切换到该页，默认加在末尾；`afterSlideIndex`
  可指定插入到哪一页后面。工具页码从 0 开始，因此用户说的第 1 页对应索引 0。
- `add_pptx_text`
  在指定页新增一个文本框，提供文字和 x/y/宽/高，几何单位为 CSS 像素。可指定初始字号（CSS 像素，默认 24）、`#RRGGBB`
  颜色（默认黑色）和加粗（默认关闭），以及上文完整的 `textStyle`
  格式字段。标题与正文分别使用文本框；返回的元素 ID 可继续用于 `edit_pptx`
  修改。
- 每次新增都校验当前文档 ID 和版本，Agent 在各步之间重新读取。请先结束行内文字输入。发生超时或错误后，应先读取实际状态，再判断是否需要再次新增。
- 新增一页和新增一个文本框各占一个**撤销/重做**步骤。例如新增页、标题、正文共需撤销三步，不是一次原子事务；后续调用失败时，之前已成功的修改仍保留且可编辑。
- 新增不会自动写入磁盘。请点击组件的**保存**按钮，下载包含修改的文件。插件重新构建后，需要重启 DSH 开发服务来注册新工具；重启前先保存已打开的文稿。

## 保存与生命周期

> **自动保存是浏览器本地的恢复缓存（IndexedDB），不会自动写入 PPTX 文件。**
> “已保存到此电脑”表示浏览器恢复副本已保存，不代表下载目录中已有文件，也不代表原附件已更新。请点击**保存**下载修改后的
> `.pptx`，并确认下载完成。

- 组件原生的**自动保存**开关默认开启，并尊重组件设置中已保存的开关偏好。每两秒检查编辑变化，将恢复快照写入当前浏览器的 IndexedDB，覆盖 Agent 和手动编辑，不会写回本机 PPTX。
- 在相同浏览器、相同会话中重新打开相同来源，会检查是否显示原生的**恢复未保存的更改？**提示。先选择恢复或放弃，再让 Agent 继续。不同附件发送记录的副本内容相互隔离，即使文件名和内容相同。本机文件按文件名和原始字节匹配，同一会话中同名且字节相同的本机副本共享恢复位置；源文件内容变化或重新上传附件会使用不同的恢复位置。
- 恢复副本以未加密的演示文稿保存在浏览器中，不包含撤销历史和文件写入权限，也无法保证保留下次快照前的修改。清理浏览器数据会移除副本；存储失败会在组件中显示错误。关闭自动保存会停止新快照；在原生恢复提示中选择放弃可删除已有副本。
- 恢复提示覆盖最近 24 小时的快照。本仓库固定接入了组件兼容修复：恢复快照后再次刷新仍可恢复，恢复或放弃某个文稿也不会抑制其他文稿的提示。显式选择放弃会删除该来源的快照。**需要长期保留文件时，请保存到本机。**
- 原生保存按钮下载新文件，不会覆盖打开的文件或聊天附件。请在浏览器下载列表中确认下载完成。
- 关闭和替换文稿时仍采用保守保护。组件没有公开的下载完成通知，因此下载不会清除插件的保护状态；选择元素或翻页也可能被标记为变化。之后关闭或切换文稿时，仍可能提示保留或丢弃内存中的编辑。
- 切换 DSH 标签、收起侧栏或开发时热更新客户端模块会保留文稿与撤销历史。关闭已加载文稿的标签后，插件会保留内存中的编辑器；未保存的文稿会显示紧凑的提示，提供**继续编辑**和**丢弃修改**操作，并跟随 DSH 的语言和主题。**隐藏提示**仅收起提示，仍会保留文稿；继续编辑只打开保留的编辑器，不会保存文件。在同一对话重新打开 PPTX 也可恢复该编辑器；关闭期间暂停 Agent 命令。完整的内存编辑器无法跨刷新或浏览器退出保留；自动保存可以在重新打开后提供最后一次完成的恢复快照，本机文件仍以显式保存为准。
- 同一对话只能由一个 PPTX 面板持有文稿。断开的连接约 15 秒后失效。正常连接时不显示状态。连接失败时可点击
  **重试**，保留当前编辑器；重连期间按钮禁用，恢复后提示和按钮消失。不会重放结果不确定的命令。
- 自动覆盖保存、母版/动画编辑、组合和图层顺序操作留待后续；富文本格式目前仅支持整个元素。组件自带的 AutoSave 用于恢复缓存，不会自动覆盖原文件。

## 数据与兼容性

Agent 调用 `open_pptx` 或 `read_pptx`
时，文件名及当前幻灯片的文字、格式、几何信息、表格数据和样式、图表数据、图片属性会进入 DSH 对话，并可能发送给该对话配置的模型服务商。插件本身不记录文稿正文日志，也不上传原始 PPTX。DSH 按自己的配置保留对话和工具调用历史。

通过聊天发送的附件走 DSH 自带的上传与附件存储流程；插件使用 DSH 身份校验，只读取当前对话已接收的文件。这与编辑器文件选择器直接打开本机文件的方式不同。

浏览器测试覆盖合成文稿中的文字、形状、表格、图片、演讲者备注、图表及其内嵌工作簿的保存与重开。这不代表所有 PowerPoint 特性都能无损往返；复杂文稿、宏、签名及第三方扩展需要单独验证。

插件提示和完整编辑器跟随 DSH 当前语言。在 DSH 的 **设置 → 常规**
中切换语言，两者会同步更新，保留当前文稿与撤销历史。插件不再提供独立语言选择器；支持中文、英文，其他 DSH 语言回退为英文。编辑器默认使用浅色主题，之后沿用已保存的主题选择，可在
**文件 → 选项 → 常规 → 查看器主题** 中切换。插件按钮和弹窗遵循 DSH 的界面风格。

## 常见问题

- **更新插件代码后：**
  先保存打开的文稿，再重启 DSH、刷新页面并重新打开文件。已打开的编辑器保留加载时的代码，仅热更新客户端模块不会更新编辑器或宿主工具。
- **发送附件后未打开 PPTX：**
  安装包用户先确认安装到了正在运行的 Web 配置并重启服务；源码开发者先执行
  `pnpm build`，启动时加载 `dsh.patch.yml`，再重新打开 DSH。
- **文件选择器没有出现：**
  使用 Chrome 或 Edge。部分内嵌浏览器虽然提供该 API，但不能正常显示系统选择器。
- **Agent 找不到编辑器：** 在同一个对话里打开 PPTX。如有连接异常提示，点击
  **重试** 并等待提示消失；先结束当前文本框输入，再重试。
- **刷新后的连接：**
  旧页面会主动释放占用；如果浏览器未送出释放请求，新页面最多等待约 20 秒，让旧占用过期后自动连接。其他仍活跃的浏览器窗口会保留所有权；请关闭其 PPTX 面板后重试。
- **找不到下载的文件：**
  检查浏览器下载列表和下载目录设置。下载失败时请保留编辑器，重新点击组件保存按钮。自动保存恢复副本不会在该目录中生成文件。

## 通过对话操作表格

可以说“添加一个项目和分数的两列表格”“把第二行分数改为 42 并居中”或“在表格末尾插入一行”。Agent 通过
`operate_pptx` 的 `add-table`、 `update-table`
操作修改单元格文字、字号、强调、颜色、填充、对齐、边距及各边边框，也可以增删行列、调整行高和相对列宽、设置表头及条纹。表格字号使用磅，几何尺寸使用像素。

每次表格操作通过组件更新一次，产生一次撤销。更新前会验证所有目标单元格。替换文字会清除该单元格的富文本分段；仅修改样式会保留其他格式。合并单元格可通过左上角起始单元格编辑，增删行列暂限无合并单元格的表格。新增和编辑表格的上限为 100 行、30 列。组件不能可靠保存表格字体名称修改，因此未开放该参数；对含多个富文本片段的单元格，仅改字体样式会被拒绝，此类表格也暂不支持增删行列，以免保存时丢失格式。明确替换文字、同时替换原富文本片段仍然支持。

表格和图表读取详情共享 128,000 字符的预算，超出部分会截断并标记；文档标识、版本和元素 ID 仍可正常读取。修改时只传需要变动的字段，不要把整个读取结果复制回修改参数。

## 通过对话操作图表

可以说“把图表数值改为 42、60、80”或“添加一个占比 30 和 70 的饼图”。 `add-chart`
支持六类图表：柱形/条形、折线、饼图、圆环、面积和雷达图。`update-chart`
可修改标题、数据、图例和标签；新建图表还支持修改类型、分组方式和条形方向。提供
`series`
会替换整个系列列表；Agent 应先读取并保留不需修改的数据。每次图表操作产生一次撤销。

已发布组件不能可靠保存导入图表的分类、类型、分组和方向修改，因此插件会拒绝这些操作，可以改为新增图表。散点/气泡图的新增和修改也未开放，因为横坐标及气泡大小不能可靠保存。网格线、底色及独立标题显隐控制同样因保存重开验证失败而未开放。特殊类型和组合图暂未接入对话。这些属于兼容性限制，并非插件新增了组件接口。

## 通过对话操作图片

在同一对话上传图片，再说“把上传的图片放在第 3 页，左边裁掉 10%，不透明度设为 80%”。Agent 通过
`list_pptx_images` 获取已接收的图片附件，再用 `add_pptx_image` 插入指定页。
`update-image`
可修改替代文字、各边裁剪比例、裁剪形状、亮度、对比度和不透明度；位置、大小、旋转和翻转沿用
`edit_pptx`。每次插入或图片更新各占一步撤销。

当前传输上限为 DSH 规范化后不超过 1
MiB 的 PNG/JPEG/WebP/GIF 图片。只允许读取当前对话已接收的用户图片附件，拒绝文件路径、远程网址及其他对话的附件。插件将校验后的字节直接交给编辑器，不放入工具返回结果；DSH 自身的图片上传与模型处理仍照常进行。
`read_pptx` 不负责识别图片内文字。

暂未开放灰度修改：已发布组件能显示灰度，但重开自己保存的文件后会丢失该标记。缺失接口和兼容性限制见[能力边界](capabilities.zh-CN.md)。
